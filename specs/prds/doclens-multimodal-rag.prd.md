## 1. 背景与目标

### 1.1 背景

作者求职 LLM 方向（具体岗位未定：算法 / 应用工程 / 后端转 AI 均在投），需要一个作品集项目，同时证明三线能力——**多模态检索（量化消融）、端到端工程（可复现可观测）、演示完成度（引用溯源）**，三线均衡，各有硬性产物。

### 1.2 产品定位（一句话）

输入一批 PDF 文档（学术论文为主线，后期扩展财报），回答"**必须看图看表才能答对**"的问题，答案带可溯源引用，点击引用直达 PDF 原页并高亮对应图表区域。

### 1.3 成功标准

| ID | 标准 | 度量方式 |
|---|---|---|
| S1 | 多模态增益量化可信 | 图表类问题检索 recall@5：full 配置 vs 纯文本 baseline 提升 ≥15 个百分点（目标值，以实测为准），且经配对检验（McNemar）达到显著 |
| S2 | 演示流畅 | 完整问答演示流程（提问→流式回答→引用点击→原页高亮）≤20 秒 |
| S3 | 可复现 | 克隆仓库，按 README 两条命令（构建 + 启动）跑通全流程 |
| S4 | 文档完备 | README 含架构图、消融指标表（含置信区间）、API 成本核算表 |

## 2. 用户与场景

### 2.1 目标用户

| 用户 | 关注点 |
|---|---|
| 主要：面试官 / 技术评审 | 10–15 分钟演示内说得清、看得见、信得过；关注能力真实性与量化，不关注产品功能广度 |
| 次要：作者本人（维护者） | 持续扩充语料、日常试用、后续迭代 |

### 2.2 用户故事

- **US1（面试官）**：我问一个必须看图的问题，希望得到正确答案且引用指向那张图，以判断多模态能力是否真实。
- **US2（技术评审）**：我希望看到消融实验表、置信区间和失败归因，以判断每个模块的贡献是否可信。
- **US3（演示观众）**：我希望点击引用就能跳到 PDF 原页看到高亮区域，直观确认答案有据可查。
- **US4（维护者）**：我希望把新 PDF 丢进目录就能自动入库，持续扩充语料而无需手动操作。

### 2.3 典型查询场景（验收基准，语料为英文论文、提问用中文）

| 类型 | 示例 | 评判要点 |
|---|---|---|
| 纯文本题 | "自注意力的复杂度是 O(n·d) 吗？" | 文本证据即可答对 |
| 图表题 | "成绩对比图里哪个考试上超过了人类考生？" | **不看图必答错**——多模态能力的核心证明 |
| 表格题 | "Table 2 里 7B 比 13B 在 MMLU 上低多少分？" | 必须读表格结构 |
| 不可回答题 | "论文里提到了作者团队的经费来源吗？" | 库中无依据时必须明确声明，不得编造 |

### 2.4 演示形态

本地演示 + 录屏（不做公网部署，避免运维与持续成本）。

## 3. 范围

### 3.1 功能范围总览

| 模块 | 职责（一句话） |
|---|---|
| 摄入与解析 | PDF → 统一文档模型（段落/表格/图表+图注/坐标/页码） |
| 索引 | 文本与图像双路向量索引 + 关键词索引 + 元数据 + 缓存 |
| 检索 | 多路召回 → 融合 → 重排，带消融配置开关 |
| 生成 | 带图上下文组装 → VLM 流式生成 → 引用映射 |
| 服务与 UI | 查询 API + 演示前端（引用溯源、原页高亮） |
| 评测 | 评测集构建、指标计算、消融实验、失败归因、报告产出 |

### 3.2 非目标（明确不做）

- 模型微调或训练
- 通用网页爬取 / 大规模数据管道
- 多用户、权限系统、高可用——定位是作品集而非生产产品
- 公网部署与运维
- 实时文档流摄入
- 产品级功能广度（广度让位于深度与量化）

## 4. 功能需求（FR）

优先级定义：**P0** 本期必须交付；**P1** 2–3 周预算内做、紧张时可砍；**P2** 本期不承诺（README 路线图）。

### FR-1 文档摄入与解析

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-1.1 | 批量导入本地 PDF，按文件指纹增量解析（已解析跳过） | P0 | 新增 PDF 无需全量重建 |
| FR-1.2 | 统一文档模型：段落/标题/表格/图片四类块，各带页码与区域坐标（供前端高亮） | P0 | 抽检 10 篇，块类型与坐标完整 |
| FR-1.3 | 图注与图表绑定；表格保留结构化表示并提供线性化文本 | P0 | 图注绑定率抽检 ≥90% |
| FR-1.4 | 解析质检报告：每篇文档的块数/图数/绑定率/空图检测 | P1 | 报告可人工审阅 |

### FR-2 多模态索引

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-2.1 | 文本块嵌入（含图注、表格线性化文本） | P0 | — |
| FR-2.2 | 图表图片嵌入（图像向量索引） | P0 | — |
| FR-2.3 | 关键词索引（BM25，中英文分词） | P0 | — |
| FR-2.4 | 元数据完整：文档/页码/类型/坐标/图片路径 | P0 | 检索结果可完整溯源 |
| FR-2.5 | 嵌入结果落盘缓存 | P0 | 增量重建不产生重复 API 费用 |
| FR-2.6 | 块级上下文增强索引（每块附生成式上下文，供消融 E 档）**（v2.0 新增）** | P0 | E 档可开启；一次性索引成本计入预算 |
| FR-2.7 | 元数据过滤能力（文档/类型过滤，服务财报语料扩展）**（v2.0 新增）** | P1 | 过滤检索可用 |

### FR-3 混合检索与重排

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-3.1 | 多路召回（文本向量/图像向量/关键词）→ 融合 → 图与图注联动去重 | P0 | 抽查 10 查询 top-5 基本相关 |
| FR-3.2 | 重排（文本路 LLM 列表式重排：候选截断后单次调用输出排序；含两种重排器对比实验位） | P0 | D 档可切换重排器 |
| FR-3.3 | 消融配置开关 **A–F 六档**（v2.0 扩展自 A–D） | P0 | 一条命令切换配置并重跑评测 |
| FR-3.4 | 跨语言检索：中文查询在英文语料上的表现与英文查询差距 ≤5pp（recall@5，同题对照）**（v2.0 新增）** | P0 | 同题中英对照测试达标 |
| FR-3.5 | 多模态重排：文本查询直接对图表候选重排（供消融 F 档）**（v2.0 新增）** | P1 | F 档可开启 |

### FR-4 带据生成

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-4.1 | 上下文组装：top-k 文本块 + 图表原图 + 表格，规模受控（图片 ≤5 张） | P0 | 单次问答成本可控 |
| FR-4.2 | VLM 流式生成，输出带 [n] 引用标注 | P0 | 引用标注格式稳定可解析 |
| FR-4.3 | 引用映射到（文档, 页, 区域坐标），供 UI 溯源 | P0 | 引用点击均指向正确原页 |
| FR-4.4 | 无依据兜底：库中无充分依据时明确声明而非编造 | P0 | 不可回答题拒绝率 ≥80%；可回答题误拒率 ≤5% |
| FR-4.5 | 多轮追问（携带上文的问题改写） | P2 | — |

### FR-5 服务与演示 UI

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-5.1 | 查询 API（SSE 流式）+ 文档/图片/PDF 页面服务 | P0 | 接口自洽可调试 |
| FR-5.2 | 演示前端：对话 + 流式输出 + 引用侧栏 + 点击引用 → PDF 原页渲染 + 区域高亮 | P0 | 完整演示流程 ≤20s |
| FR-5.3 | 检索过程可视化（各路命中与分数并列展示） | P1 | UI 可见检索细节 |
| FR-5.4 | 开发期调试界面 | P1 | 迭代效率可感知提升 |

### FR-6 评测与消融

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-6.1 | 评测集构建：**约 165 题 = 可回答 150 题（三类各 50）+ 不可回答 15 题**（v2.0 修订）；半自动出题 + 人工审核；BM25 基线剔除"字面重叠即可召回"的伪题 | P0 | 题集定稿并版本化 |
| FR-6.2 | 指标体系：recall@5/10、MRR、nDCG@10（按题型分层）；答案质量（双模型 judge 交叉 + 人工抽检）；引用命中率 | P0 | 指标可自动计算 |
| FR-6.3 | 配对统计检验：同批题跨配置，McNemar 检验 + bootstrap 置信区间**（v2.0 新增）** | P0 | 消融结论附显著性 |
| FR-6.4 | 失败归因分析：每道错题定位首个失败阶段（F0 标注错/F1 解析缺失/F2 召回缺失/F3 融合错排/F4 重排伤害/F5 生成失败/F6 兜底误触发）**（v2.0 新增）** | P0 | 归因分布入报告 |
| FR-6.5 | 消融报告 `reports/ablation.md`：A–F 对比表 + 置信区间 + 归因叙事 | P0 | 报告产出且结论可复核 |
| FR-6.6 | 一键评测命令 | P0 | 单命令跑完整评测 |

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| FR-7.1 | README 两条命令跑通（构建 + 启动） | P0 | 全新克隆机器（Win11）验证 |
| FR-7.2 | 依赖版本锁定 | P0 | 锁定文件入库 |
| FR-7.3 | API 成本核算表 | P0 | M0 产出，随实测更新 |

### P1 汇总（预算内可砍）

查询改写（仅限无重排配置下评估增益）、检索过程可视化（FR-5.3）、调试界面（FR-5.4）、元数据过滤（FR-2.7）、多模态重排（FR-3.5）、解析质检报告（FR-1.4）、财报泛化包（3–5 篇中文文字版 PDF，演示跨领域泛化）。

### P2 路线图（本期不承诺）

ColPali 式视觉文档检索对比、公网部署、VLM 图表描述增强（可作为消融扩展档）。

## 5. 非功能需求（NFR）

| 类别 | 需求 |
|---|---|
| 性能 | 检索 P95 <2s；生成首 token <5s；演示全流程 ≤20s；单次问答图片上下文 ≤5 张 |
| 成本 | 全量构建 + 一轮完整消融（A–F）API 费用 ≤ 几十元人民币；上下文增强索引一次性成本 ~$1 量级；M0 产出精确核算表 |
| 可复现 | 两条命令跑通；依赖锁定；解析与嵌入结果缓存；固定随机种子 |
| 环境 | Windows 11、无 NVIDIA GPU；模型能力经云端 API（火山方舟，单供应商）；本地组件 CPU 可跑；Python 3.12 |
| 安全 | API key 仅存 .env（不入库）；解析默认本机执行（文档不出网）；日志脱敏 |
| 可观测 | 每次问答落 trace（各路检索分数、耗时、token 用量） |

## 6. 数据需求

| 数据集 | 规模 | 用途 |
|---|---|---|
| 主语料：arXiv cs.CL（2024–2026，图表密集） | ~100 篇 | 检索池 |
| 出题集 | 其中 30 篇 | 评测题来源（每篇 ~5 题） |
| 干扰集 | 其余 ~70 篇 | 只入库不出题，考验检索区分度 |
| 财报泛化包 | 3–5 篇中文文字版 PDF | P1，跨领域泛化演示 |
| 评测集 | ~165 题（可回答 150 + 不可回答 15） | 消融与验收 |

**评测集构建流程**：解析 → 抽取图表/表格 → VLM 半自动出题（含候选答案与 gold 证据引用）→ 人工审核修订 → BM25 基线剔除伪题 → 定稿版本化。

**合规**：全部使用公开数据集；用途为研究与作品集展示；不 redistribute 原始 PDF（仓库只含下载脚本与列表）。

## 7. 评测需求细化

### 7.1 消融阶梯（v2.0 扩展为 A–F）

| 档 | 配置 | 证明什么 |
|---|---|---|
| A | 纯文本 RAG（文本向量 + BM25） | 起点 baseline |
| B | A + 图注/表格线性化文本入库 | "图表的文字代理"价值 |
| C | B + 图像嵌入检索 | 跨模态检索真实增益 |
| D | C + 重排 | 精排贡献（含重排器对比实验） |
| E | D + 块级上下文增强索引 | 索引侧增强增益 |
| F | E + 多模态重排 | 跨模态精排增益 |

### 7.2 统计与报告要求

- 配对设计：同批题跨配置，报告配对差值 + McNemar 显著性 + bootstrap 95% CI
- 分层报告：按题型（纯文本/图表/表格/不可回答）分别统计
- 失败归因：F0–F6 分型分布（框架见调研笔记 §4）
- 结论措辞规范：未达显著的差异表述为"趋势"，不宣称显著

### 7.3 外部基准（候选，未进本期承诺）

MP-DocVQA / M3DocVQA（端到端）、ViDoRe（检索层）、FinanceBench（财报阶段）——获取与许可待核实，核实后另行提案。

## 12. 术语表

| 术语 | 定义 |
|---|---|
| RAG | 检索增强生成：先检索证据再生成回答 |
