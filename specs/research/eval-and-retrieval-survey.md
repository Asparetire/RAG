## 2. 评测：评价方法论（v0.1 基线知识，部分为自研设计）

### 2.1 检索层指标（成熟做法，直接采用）
- recall@5 / recall@10（gold 证据是否进 top-k——RAG 场景首要指标）、MRR、nDCG@10
- **分层统计**：按题型（纯文本/图表/表格）分别报告，消融结论按题型解读
- k 的选择：与下游上下文组装窗口一致（top-k=5 文本块 + ≤5 图）

### 2.2 答案质量指标〔待核实〕
- ANLS（DocVQA 系标准）：归一化编辑距离相似度，低于阈值记 0〔公式与阈值待核实〕
- LLM-as-judge 协议要点：锚定 rubric 绝对打分；成对比较交换位置；双 judge 交叉报告一致率；judge 与被评模型不同源
- 引用质量（借鉴 ALCE）：citation recall / precision〔计算细节待核实〕

### 2.3 RAG 框架（是否集成待定）〔待核实〕
- RAGAS 四指标定义；多模态支持现状；倾向自实现轻量版

### 2.4 评测集构建方法论（并入 M5 设计）
- LLM/VLM 半自动出题 + 人工审核；**加入不可回答题**（MMLongBench-Doc / RGB 均有此设计）；难度/题型分层；用 BM25 baseline 剔除"字面重叠即可召回"的伪题

### 2.5 统计功效（自研决策，确定性）
- 150 题总体比例 95% CI 半宽约 ±8pp；分题型 n=50 时约 ±14pp——未配对比较撑不起 15pp 量级结论
- **对策**：同一批题跨配置配对跑，McNemar 检验 + bootstrap CI；样本不足的结论措辞降级为"趋势"

## 3. 检索方法（v1.0 已核实，来源见 §7）

### 3.1 查询侧

| 方法 | 已核实增益 | 成本 | 判定 |
|---|---|---|---|
| HyDE [2] | 零样本检索器上强（Contriever DL19 nDCG@10 44.5→61.3 [2]）；但 BGE-M3 为有监督模型，增益未必迁移；专业领域失效（FiQA 24.5→27.3，仍低于微调基线 32.9 [2]）；Anthropic 实测摘要索引/HyDE 表现低 [1] | 每查询 +1 LLM 调用 | ❌ 跳过（低优先） |
| 多查询扩展 [22][23] | MS MARCO Recall@1K 87.82→90.61 [22]；**但生产 RAG 证据：有重排时增益被抵消，Hit@10 0.51→0.48（负收益）** [23]；BM25 召回 +2.6~2.8 [22] | 每查询 N 倍嵌入 + LLM | 🔶 仅在"无重排"消融配置下测召回 |
| 查询分解 | 无独立大规模量化证据；Qdrant 官方教程存在 [13 系] | — | 不承诺 |
| Step-back [17] | MMLU 物理 +7%/化学 +11%、TimeQA +27% [17]——面向知识型 QA 非文档检索；论文自述适用面窄 | 每查询 +LLM | ❌ 跳过 |

### 3.2 索引侧

| 方法 | 已核实增益 | 成本 | 判定 |
|---|---|---|---|
| **Contextual retrieval** [1] | 1-recall@20 失败率：5.7% → 3.7%（上下文嵌入，-35%）→ 2.9%（+上下文 BM25，-49%）→ 1.9%（+重排，-67%）[1] | prompt caching 下 $1.02/百万文档 token（Claude）[1]；我们 100 篇 ≈ 1.2M token → **一次性 ~$1**，用 Qwen 更便宜 | ✅ **E 档首选** |
| Late chunking [3] | 平均 +1.9 nDCG@10（3.63% 相对）[3]；但需 token 级嵌入输出——API-only 栈不可行 | — | ❌ 跳过（API 限制，已确认） |
| 父子块/句子窗口 | 方法成熟（LlamaIndex SentenceWindow/AutoMerging [20 系]）；**具体增益数字未核实** | 实现轻（Qdrant payload 存父块引用） | 🔶 F 档试验 |
| 结构感知分块 [4][3] | ColPali 论文："优化摄入管道比换嵌入模型收益更大" [4]；**表格：解析文本+BM25 46.5 vs VLM 图注+BM25 35.4（TabFQuAD）——表格必须走解析文本** [4]；信息图：图注有益（BM25 62.9→70.0）[4]；语义分块不优于句子/固定分块 [3] | — | ✅ 验证了现有设计（MinerU 线性化表格 + 图注绑定图表） |
| doc2query/docTTTTTquery [21] | BM25-only 时代 MS MARCO MRR@10 18.6→27.2 [21]；现代混合+重排下增益未核实 | 每块 LLM 调用 | ❌ 跳过 |
| 元数据过滤 [15] | Qdrant 原生 must/should + payload 索引；对中文财报语料有用 | 零成本 | ✅ 采用（基础设施） |

**Contextual retrieval 实现要点** [1]：每块生成 50–100 token 上下文前缀，**同时用于嵌入与 BM25 索引**；检索先取 top-150 再重排至 top-20（top-20 优于 top-10/5）。

### 3.3 融合与重排

**RRF vs 加权** [13]：RRF 免调参、对分数尺度稳健；Qdrant 的 RRF 支持**每路权重 w_r**（公式 score = Σ 1/(k + rank/w)，k=2 默认）——不换 DBSF 也能做路间调权。→ 保持 RRF 默认 + 权重实验位。

**重排器对比**（Qwen3 官方博客 [9]，基于 Qwen3-Embedding-0.6B 召回 top-100 重排）：

| 模型 | MTEB-R | CMTEB-R(中) | MMTEB-R | MLDR(长文档) |
|---|---|---|---|---|
| bge-reranker-v2-m3 (0.6B) | 57.03 | **72.16** | 58.36 | 59.51 |
| Qwen3-Reranker-0.6B | 65.80 | 71.31 | 66.36 | 67.28 |
| Qwen3-Reranker-4B | 69.76 | 75.94 | **72.74** | 69.97 |
| Qwen3-Reranker-8B | 69.02 | **77.45** | 72.94 | 70.19 |

- 中文 0.6B 档 BGE 略优（72.16 vs 71.31），多语言/长文档 Qwen3 大幅领先（+8~14 点）
- 我们（英文 arXiv 主线 + 后期中文财报）→ **Qwen3-Reranker-4B 平衡最佳**；SiliconFlow 同端点切换，重排器支持 instruction 参数 [12]
- 判定：✅ **E 档**（D 档内做 bge vs Qwen3-4B 对比）

**重排增益量级**（原问题"重排通常加多少点"的答案）：
- RankGPT [16]：BEIR 平均，BM25 top-100 重排 43.42 → 49.37（gpt-3.5）/ 53.68（gpt-4），即 **+6~+10 nDCG@10**
- Anthropic [1]：混合+上下文检索之上，重排再降 **34% 相对失败率**（2.9%→1.9%）
- BGE-M3 [6]：MIRACL dense 69.2 → 三路自融合 71.5（+2.3，同族证据）

**列表式 LLM 重排（RankGPT）** [16]：GPT-4 排列式平均 +2.3~+2.7 vs monoT5-3B；滑窗（窗口 20/步长 10）处理 100 候选；低资源语言失效；成本高（论文方案：gpt-3.5 预筛 30 → gpt-4，成本降至 1/5）。→ 🔶 备选对比实验。

**多模态重排**：Qwen3-VL-Reranker-2B/8B（2026-01 [11]）为首个大厂托管多模态重排器系，query/doc 均可为文本/图片/混合；**SiliconFlow /rerank 已托管 8B**（主代理直接核实 [12]）。→ 🔶 **F 档**（文本查询直接对图表候选重排，强化三路召回的多模态特性）。

### 3.4 视觉检索（ColPali 系）

- ViDoRe 榜 [5]：colpali 81.3 / colpali-v1.3 84.8 / colqwen2-v1.0 89.3 / colqwen2.5-v0.2 89.4，vs 经典管道最好 ~66–67 [4] → **+15~23 点**
- ColPali Table 2 经典管道明细 [4]：Unstructured+OCR+BM25 平均 65.5；+BGE-M3 66.1；图注+BM25 65.1；图注+BGE-M3 67.0；**Jina-CLIP 仅 17.7**（→ 弃用 CLIP 系、选 Qwen3-VL-Embedding 被数据验证）
- 无主流托管 API（第三方 ColiVara/Mixpeek；自部署 BentoML/Cerebrium [5]）；Qdrant 支持 multi-vector max_sim（v1.10+）[14]；token pooling 可减 66.7% 向量数、保持 97.8% 性能 [5]
- **关键事实**：Qwen3-VL-Embedding-8B（我们已采用，SiliconFlow 已托管 [12]）MMEB-V2 VisDoc **83.3** [10] ≈ colpali-v1.3（84.8）水平的 dense 单向量——**当前栈已接近 ColPali 级视觉检索，无需 multi-vector 成本**
- 判定：❌ 本期跳过 ColPali（无 GPU/托管）；P2 路线图保留对比实验位

### 3.5 跨语言（中文查询→英文文档）

- BGE-M3 [6][8]：100+ 语言；MKQA 跨语言 **dense 优势明显、sparse/BM25 跨语言弱**（词汇重合小）[8]；MLRB 长文档 sparse 显著 > dense（BM25 路对长文档重要）[8]
- 跨语言排序研究 [24]：CLIR 训练的 dense **一致优于词汇匹配与文档翻译管道**——优先多语言嵌入而非查询翻译
- **落地约束（写入 M3 计划）**：中文查询直接进 BGE-M3 dense 路；**BM25 路对 zh→en 查询降权或旁路**；不加查询翻译
- 升级选项：Qwen3-Embedding-8B MMTEB 70.58 vs BGE-M3 59.56 [9]——跨语言若成瓶颈，文本嵌入升级是现成选项

### 3.6 检索后处理

| 方法 | 已核实增益 | 判定 |
|---|---|---|
| 上下文压缩（LongLLMLingua [20]） | NQ +21.4%、~4x token 缩减、延迟 1.4–2.6x 加速 | 🔶 F 档（成本控制位） |

## 4. 失败归因分析框架（自研方法，非调研）

消融报告只给聚合数字说服力不足；对每道错题做**首个失败阶段**归因，聚合后解释"每个方法到底修好了哪类失败"。

### 4.1 失败分型（按管道顺序定位第一失败点）

| 编号 | 分型 | 判定标准 |
|---|---|---|
| F0 | 标注错误 | gold 标注本身有误（人工复核裁定） |
| F1 | 解析缺失 | gold 块/图从未进入索引（图注未绑定、阅读顺序断裂、裁剪失败） |
| F2 | 召回缺失 | gold 在索引中但未进任何一路 top-K（细分：文本路/图像路/BM25 各自是否命中） |
| F3 | 融合错排 | gold 被召回但 RRF 后跌出截断线 |
| F4 | 重排伤害 | 重排前在截断线内、重排后跌出 |
| F5 | 生成失败 | 证据已在上下文中，答案仍错（VLM 读图错/漏看表格/推理错） |
| F6 | 兜底误触发 | 有证据却回答"无依据" |

### 4.2 报告呈现
- 每配置 × 每题型：失败分型分布堆叠图
- 关键叙事例："C 档把 F2(图像路未命中) 从 34% 降到 12%，但引入少量 F4；D 档修复了后者"
- F0 比例 >5% 时先修评测集再跑消融

## 6. PRD 修订提案（草案——确认后写入 PRD 并重新过确认门）

**修订 1：R3 消融阶梯扩展 A–D → A–F**
- E = D + contextual retrieval + 重排器升级（D 内先做 bge vs Qwen3-Reranker-4B 对比，E 取优者 + contextual）
- F = E + 多模态重排（Qwen3-VL-Reranker-8B 图像路）；句子窗口/父子块作为 F 内可选子实验
- 各档切分在 S1（M3 实现计划）中细化；验收标准同步扩展

**修订 2：R6 评测扩展**
- 评测集加入不可回答题（unanswerable，~10%，约 15 题）
- 指标报告必须含配对检验（McNemar）与 bootstrap CI
- 消融报告必须含失败归因分析（§4 框架）
- 外部基准验证一项维持〔待核实〕，不进本次修订

**修订 3（设计约束，写入 S1 计划输入，非 PRD 变更）**
- 跨语言路由：中文查询直接进 dense 路；BM25 路对 zh→en 降权或旁路；不加查询翻译
- 表格索引走 MinerU 解析文本（已验证优于 VLM 图注）；图注仅用于图表
- 上下文组装：重排后 top-20 内截断、首尾优先放置
